# [portfolio] 승인 게이트

mode: portfolio

- 공부할 것: 인증과 인가, 권한 분리, 승인 범위, nonce, 만료, compare-and-swap, TOCTOU, 승인과 실제 적용 사이의 변화.
- 네가 결정할 것: 승인에 묶을 작업·명세·커밋·계획·환경·정책·검사·모드·학습 근거, 만료 기준, 재사용 거절, 모델과 실제 적용 실행기의 권한.
- 먼저 직접 만들 것: 승인 문맥과 상태 전환표. 학습 결정을 변경 승인과 구분하고 소유자 확인 지점을 고른다.
- 비교할 선택지: 일반 '승인됨' 플래그, 작업 ID만 묶은 승인, 전체 실행 문맥에 묶은 일회성 승인.
- 네가 고를 실험: 승인 후 코드 변경, plan 변경, 다른 환경, 모드 변경, 만료, nonce 재사용, 동시 소비, 미등록 사용자, 비어 있는 학습 근거.
- 네가 해석할 것: 어떤 요청을 거절했는지, 오탐과 사용 부담, 적용 직전 다시 확인해야 할 값.
- 실제 완료 근거: 변경·만료·재사용·잘못된 사용자와 환경은 거절, 유효한 문맥은 한 번 소비, 적용 결과 불명은 대조, 게이트 정책을 작업자가 수정할 수 없음.
- 설명 질문: READY 승인과 운영 apply 승인이 왜 다른가? 사람이 클릭한 이후에도 검사가 필요한 이유는 무엇인가?

소유자 체크포인트: 설계 결정 → 실험 해석 → 핵심 설명.

현재 상태: 제안. 실제 구현·실험·학습 결과는 아직 없다.
