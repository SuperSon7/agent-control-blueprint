# [portfolio] 작업 복구

mode: portfolio

- 공부할 것: 메모리와 내구성 저장의 차이, 트랜잭션, 상태 전환, 체크포인트, 프로세스 수명, lease와 fencing token, 외부 실행 결과 대조.
- 네가 결정할 것: 무엇을 저장해야 재시작할 수 있는지, 어떤 상태는 재개하고 어떤 상태는 외부 결과부터 확인해야 하는지, 만료된 lease와 살아 있는 writer를 어떻게 다룰지.
- 먼저 직접 만들 것: 상태 전환표와 재개 조건표. 상태가 하나 추가되면 보존·재개·취소 조건을 설명한다.
- 비교할 선택지: 메모리만 유지, 파일 저장, SQLite 트랜잭션. 모두 같은 실패 시나리오로 판단한다.
- 네가 고를 실험: DB 기록 직전·직후 종료, 실행 중 종료, 오래된 PID 재사용, lease 만료 뒤 이전 writer 생존, 게시 성공 뒤 결과 기록 전 종료.
- 네가 해석할 것: 어떤 자료가 살아남았는지, 재개 가능한지, 결과 불명 상태를 왜 다시 실행하면 안 되는지.
- 실제 완료 근거: 재시작 뒤 작업 보존, writer 중복 없음, 잘못된 PID 종료 없음, 외부 변경 결과 불명은 대조 후 진행. 실행 로그와 실패 위치를 연결한다.
- 설명 질문: 작업의 재개와 외부 작업의 재실행은 어떻게 다른가? lease만 만료되면 새 writer를 시작해도 되는가?

소유자 체크포인트: 설계 결정 → 실험 해석 → 핵심 설명.

현재 상태: 제안. 실제 구현·실험·학습 결과는 아직 없다.
