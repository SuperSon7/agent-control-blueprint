# 학습하며 구현하고 근거 남기기

현재 이슈의 mode와 학습 목표, 소유자 단계, 기존 응답을 읽는다. portfolio 모드에서는 선택한 역량 한두 개를 중심으로 진행하고 일반 구현 작업까지 모두 수업으로 확대하지 않는다.

사용자에게 의미 있는 선택지와 판단 기준, 작은 실패 실험안을 먼저 준비한다. 답을 유도하기 전에 사용자의 가설과 선택 이유를 기록한다. 복구·중복 방지·승인 게이트 이슈라면 해당 부분만 [핵심 설계 학습](references/core-topics.md)을 읽는다.

소유자 체크포인트는 설계 결정, 실험 해석, 핵심 설명이다. 필요한 자료와 비교안을 구체적으로 준비한 다음 한 번에 하나의 자기 설명 요청을 한다. 이미 제공한 응답은 다시 묻지 않는다. 사용자의 요청이 학습 진행을 요구하므로 이 지점에서 기다리되, 루틴 검사마다 승인을 묻지 않는다.

답을 대신 작성하거나 침묵을 동의로 취급하지 않는다. 독립적으로 할 수 있는 자료 준비는 진행하고, 응답이 필요한 단계는 보존한다. 작업 관리자가 없다면 현재 단계·대기 이유·근거 위치를 프로젝트의 학습 기록에 남긴다.

사용자가 직접 맡은 설계 또는 코드 범위는 먼저 사용자 결과를 기다린다. AI가 초안을 요청받으면 지원 범위를 표시하고, 이를 사용자의 구현이나 판단으로 재분류하지 않는다.

선택한 실험을 실제 실행하고 결과를 전달한다. 소유자가 예상과 비교해 설계 유지·변경 이유를 적게 한다. 실제 실행하지 않은 결과·측정값은 작성하지 않는다. 위험한 실험에는 프로젝트의 공통 권한·환경 게이트를 적용한다.

최종 구현과 실제 검사 후 핵심 설명을 확인하고 [근거 기록](references/evidence.md)에 따라 사례를 정리한다. 모델의 평가만으로 이해를 인증하지 않는다. 설명의 빈틈은 한계나 후속 학습으로 기록한다.

학습 호출은 구현 이슈 예산을 공유하고, 기본 학습 준비와 실험은 30분으로 시작한다. 응답 대기에는 모델을 호출하지 않는다. 시간 부족이나 모드 변경은 사용자가 명시적으로 선택하며 미완성 학습 근거를 완료로 표시하지 않는다.

이 스킬은 실행 정책이나 외부 게시 권한을 변경하지 않는다. 사용자 학습 응답과 변경·배포 승인은 서로 다른 기록이다.
