# 핵심 설계 학습

현재 이슈에 해당하는 절차만 읽는다. 질문과 실패 지점을 미리 모두 나열해 수업을 늘리지 않는다.

## 복구

메모리와 저장 상태, 커밋 전후 종료, 프로세스 생존, lease·fencing, 재개와 외부 실행 결과 대조를 비교한다. 사용자가 저장 항목과 재개 조건표를 먼저 만들게 한다. writer가 살아 있는데 lease만 만료된 실험과 외부 성공 뒤 로컬 기록이 없는 실험을 함께 고려한다.

## 중복 방지

요청 ID의 범위와 수명, inbox의 unique constraint, 트랜잭션, 수신 offset 순서, outbox 전송의 중복 가능성을 다룬다. 사전 조회 후 insert와 원자적 제약의 차이를 동시 입력으로 검증한다. 동일 내용의 새 요청과 동일 이벤트 재전송을 구분한다. DB 제약으로 외부 부작용까지 정확히 한 번을 주장하지 않는다.

## 승인

작업·명세·커밋·계획·환경·정책·검사·모드·학습 근거를 묶고 만료·일회 소비·적용 직전 재확인을 검증한다. 사용자 ID와 nonce의 역할을 구분한다. 사용자의 학습 결정을 변경 또는 배포 승인으로 재사용하지 않는다. 승인 후 변화·동시 소비·잘못된 환경의 거절을 실험한다.
