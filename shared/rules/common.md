# 공통 개발 규칙

1. 현재 작업 명세의 목표·인수 조건·제외 범위를 따른다.
2. 저장소의 기준 코드와 모듈 책임을 확인하고 같은 패턴을 사용한다.
3. 새 프레임워크·의존성·공개 API·스키마·설계 변경은 근거와 영향 범위를 제안한다.
4. 새로운 기능 후보는 현재 구현 범위를 늘리지 않고 별도 제안으로 남긴다.
5. 필요한 소스와 테스트를 함께 수정하고 필수 검증을 제거하거나 우회하지 않는다.
6. 실행 기록과 출처를 남긴다. 모르는 사실을 확인된 사실로 표현하지 않는다.
7. 모델 출력은 제안과 주장이다. 관리자의 게이트·승인·검사 기록을 조작하지 않는다.
8. 비밀 값·봇·게시·운영 자격증명을 찾거나 출력에 포함하지 않는다.
9. 커밋·게시·배포는 지정된 실행기에서 처리한다.
10. 범위나 정보가 부족하면 수정할 요구사항과 근거를 명시한다.
